# For Each制御変数代入境界の真因仮説

## 直接原因

`evaluateForEachStatement`は列挙要素を制御変数へ代入する
`Environment.set`を、要素ごとの本体実行を包む`try`の外で呼び出している。
宣言型へのLet変換が失敗すると、For Each文全体のエラー境界へ例外が伝播する。

## 設計上の真因仮説

VBAでは制御変数への暗黙のLet代入も反復ごとの実行境界だが、ランナーは
ASTのFor Each文単位だけをエラー処理境界としてモデル化している。そのため、
`On Error Resume Next`が失敗要素を越えて次の列挙要素へ進む状態遷移を表現できない。

## 確認済み経路

- Long制御変数と混在配列で、2番目の文字列要素の代入がError 13になる。
- 配列・Collectionはいずれも同じ無保護の制御変数代入へ収束する。
- 失敗はループ本体の式ではなく、制御変数代入時に発生する。

## 除外経路

- 配列のflatten処理やCollection要素抽出自体の失敗ではない。
- Variant制御変数では型変換境界を通らないため、この仮説の直接再現条件ではない。

## 対処判断

期待値がExcelで確認されるまで実装変更は行わない。確認後、要素代入を
反復単位のエラー境界として扱い、Resume Next時に次要素へ進める設計とする。
配列・Collection、通常の本体エラー、未処理エラーを分けた回帰テストを追加する。
