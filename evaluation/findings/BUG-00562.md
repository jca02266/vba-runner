# 数値リテラル直後の`^`境界を構文エラーにできない

## 事象

Excelでは次の式がコンパイル時の「構文エラー」になる。

```vba
CStr(2^(-1))
CStr(2^&H3)
CStr(2^&O3)
```

修正前のvba-runnerはこれらを受理していた。

## 横展開

`^`の前に空白を置く通常の冪乗、LongLongリテラル単体、符号付き右辺、
16進・8進リテラル境界を確認した。修正対象は数値リテラルの後置構文と
`index-expression`の左辺分類に限定した。

## 真因分析

MS-VBALは`INTEGER = integer-literal ["%" / "&" / "^"]`と定義し、
同時に`expression "^" expression`を冪乗演算として定義している。空白なしの
`2^...`では前者のLongLongサフィックス境界を維持する必要がある。さらに、
`index-expression`の左辺は`l-expression`であり、数値リテラルは該当しない。

修正前はLexerがこの境界を冪乗演算子として渡し、Parserも数値リテラルへの
括弧後置をCallExpressionとして受理していた。

## 回帰テスト

`tests/vba/CompileError.bas`に3ケースを追加し、生成された
`tests/spec/vba_compile_error.test.ts`で構文エラーを検証する。Lexer/Parserの修正後、
CompileError、冪乗境界、演算子回帰テストが通過した。
