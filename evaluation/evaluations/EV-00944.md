## 評価内容

`MIRR(ValueArray() As Double, ...)`の第1引数について、可変長・固定長の`Double()`、
各数値配列型、`Variant()`、配列を保持する`Variant`、直接`Array(...)`式を個別に
コンパイル・実行し、静的な配列宣言型と実行時の値変換を区別して評価する。

`Currency()`配列については、Excelで「型が一致しません: 配列またはユーザー定義型を
指定してください。」となることを`tests/vba/CompileError.bas`で確定済みとする。
直接`Array(...)`式も同じコンパイルエラーとなることを実機で確定済みである。これらの
`Integer()`配列も同じコンパイルエラーとなることを実機で確定済みである。これらの
`Long()`配列も同じコンパイルエラーとなることを実機で確定済みである。これらの
`Single()`配列も同じコンパイルエラーとなることを実機で確定済みである。これらの
ケースは`Application.Run`で実行できないため、Excel孤立キューには含めない。

## 実施方法

次の自己完結した手続きを、`DECLARATION`を表の各行へ置き換えて1件ずつ実行する。

```vba
Sub Probe()
    Const caseName As String = "CASE_LABEL"
    DECLARATION
    flows(0) = -100: flows(1) = 50: flows(2) = 100
    On Error Resume Next
    Err.Clear
    Dim value As Variant, errNo As Long
    value = MIRR(flows, 0.1, 0.12)
    errNo = Err.Number
    Debug.Print "XL-246 CASE=" & caseName & " COMPILE=0 ERR=" & CStr(errNo) & _
        " VALUE=[" & CStr(value) & _
        "] TYPE=" & TypeName(value)
    On Error GoTo 0
End Sub
```

| ケース | `DECLARATION` |
|---|---|
| DYNAMIC_DOUBLE | `Dim flows() As Double: ReDim flows(0 To 2)` |
| FIXED_DOUBLE | `Dim flows(0 To 2) As Double` |
| SINGLE | `Dim flows(0 To 2) As Single` |
| LONG | `Dim flows(0 To 2) As Long` |
| INTEGER | `Dim flows(0 To 2) As Integer` |
| VARIANT_ARRAY | `Dim flows(0 To 2) As Variant` |

配列を保持する`Variant`と直接配列式は、次の各手続きを個別に実行する。

```vba
Sub ProbeVariantValue()
    Dim flows As Variant, value As Variant, errNo As Long
    flows = Array(-100, 50, 100)
    On Error Resume Next
    Err.Clear
    value = Empty
    value = MIRR(flows, 0.1, 0.12)
    errNo = Err.Number
    Debug.Print "XL-246 CASE=VARIANT_VALUE COMPILE=0 ERR=" & CStr(errNo) & _
        " VALUE=[" & CStr(value) & "] TYPE=" & TypeName(value)
    On Error GoTo 0
End Sub

Sub ProbeDirectArray()
    Dim value As Variant, errNo As Long
    On Error Resume Next
    Err.Clear
    value = Empty
    value = MIRR(Array(-100, 50, 100), 0.1, 0.12)
    errNo = Err.Number
    Debug.Print "XL-246 CASE=DIRECT_ARRAY COMPILE=0 ERR=" & CStr(errNo) & _
        " VALUE=[" & CStr(value) & "] TYPE=" & TypeName(value)
    On Error GoTo 0
End Sub
```

通常6ケースでは`CASE_LABEL`も表のケース名へ置き換える。XL-246は6ケースを束ねる
論理IDとし、実機プローブは各ケースを別々のコンパイル単位へ置く。コンパイル成功時は
`XL-246 CASE=<name> COMPILE=0 ERR=<number> VALUE=[<value>] TYPE=<type>`、失敗時は
`XL-246 CASE=<name> COMPILE=ERROR MESSAGE=[<message>]`の形へ集約する。

## 期待値

プログラム上の期待結果は、6ケースそれぞれについてExcelのコンパイル可否を記録し、
実行へ到達したケースでは`Err.Number`、値、`TypeName`がRunnerと一致することである。
Currency配列と直接`Array(...)`式は別途コンパイルエラーとして確定している。
MS-VBALの一般規則では可変長`Double()`だけが仮引数の宣言型と完全一致するが、標準
ライブラリ手続きの引数渡しには実装固有差が許されるため、Excel結果を確認するまで
他ケースのコンパイル可否を確定値にしない。

## 結果

Runner実測出力:

```text
DYNAMIC_DOUBLE COMPILE=0 ERR=0 VALUE=[0.24899959967967988] TYPE=Double
FIXED_DOUBLE COMPILE=0 ERR=0 VALUE=[0.24899959967967988] TYPE=Double
SINGLE COMPILE=0 ERR=0 VALUE=[0.24899959967967988] TYPE=Double
CURRENCY COMPILE=0 ERR=0 VALUE=[0.24899959967967988] TYPE=Double
LONG COMPILE=0 ERR=0 VALUE=[0.24899959967967988] TYPE=Double
INTEGER COMPILE=0 ERR=0 VALUE=[0.24899959967967988] TYPE=Double
VARIANT_ARRAY COMPILE=0 ERR=0 VALUE=[0.24899959967967988] TYPE=Double
VARIANT_VALUE COMPILE=13 MESSAGE=[Type mismatch: array or user-defined type required]
```

Excel実機確認済み:

```text
XL-246 CASE=CURRENCY COMPILE=ERROR MESSAGE=[型が一致しません: 配列またはユーザー定義型を指定してください。]
XL-246 CASE=DIRECT_ARRAY COMPILE=ERROR MESSAGE=[型が一致しません: 配列またはユーザー定義型を指定してください。]
XL-246 CASE=INTEGER COMPILE=ERROR MESSAGE=[型が一致しません: 配列またはユーザー定義型を指定してください。]
XL-246 CASE=LONG COMPILE=ERROR MESSAGE=[型が一致しません: 配列またはユーザー定義型を指定してください。]
XL-246 CASE=SINGLE COMPILE=ERROR MESSAGE=[型が一致しません: 配列またはユーザー定義型を指定してください。]
```

Runnerの組み込み引数仕様は配列であることだけを保持し、`Double`要素型を保持しない。
そのため静的配列は要素型に関係なく実行へ進み、配列宣言でない`Variant`変数だけを
precheckで拒否した。Excel実機のコンパイル可否は未取得である。

## 判定

判定状態: needs-excel

コンパイルエラー候補を通常の実機キューへ混在させないよう、9ケースを1ケース1ブックへ
分離したプローブを準備済みである。開発側の分離ソースハッシュと生成済みブックの準備
スタンプが一致したため、Windowsで結果を取得するまで`needs-excel`とする。
