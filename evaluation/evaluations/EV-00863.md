## 評価内容

エラー処理のカバレッジが低いResume制御について、標準Subのエラー後の次文継続、
ラベルへの再開、エラー発生文の再実行を一つの状態遷移マトリックスとして確認する。

## 実施方法

```vba
Function ProbeResume() As String
    Dim value As Long
    On Error Resume Next
    GoSub Worker
    value = 7
    ProbeResume = CStr(Err.Number) & ":" & CStr(value)
    Exit Function
Worker:
    Err.Raise 6
    Return
End Function

Function ProbeResumeLabel() As String
    On Error GoTo Handler
    GoSub Worker
    ProbeResumeLabel = "bad"
    Exit Function
Worker:
    Err.Raise 5
    Return
Handler:
    Resume Recover
Recover:
    ProbeResumeLabel = "R" & CStr(Err.Number)
End Function

Function ProbeDoResume() As String
    Dim attempts As Long
    On Error GoTo Handler
    GoSub Worker
    ProbeDoResume = "after"
    Exit Function
Worker:
    attempts = attempts + 1
    If attempts = 1 Then Err.Raise 5
    Return
Handler:
    attempts = 2
    Resume
End Function
```

3つの関数を独立に呼び出し、エラー番号、再開位置、再実行後の戻り値を記録した。

## 期待値

プログラム上の期待出力: `ProbeResume=6:1`、`ProbeResumeLabel=R0`、
`ProbeDoResume=after` となること。文章としては、各Resume形式が意図した命令位置へ
遷移し、標準Subのエラー状態が復帰後に壊れないことである。

## 結果

Runner実測出力:

```text
ProbeResume=6:1
ProbeResumeLabel=R0
ProbeDoResume=after
```

標準Subの全ケースが期待したエラー番号・再開位置・再実行後の戻り値になり、
Runnerの再現可能なバグは確認できなかった。Excel固有の差異はこの評価では判定していない。

## 判定

判定状態: verified-no-bug

対象のRunner状態遷移は検証済みで、新規Findingは作成しない。クラス境界、ネストイベント、
外部COMのResume契約は今回の対象外として、必要になった場合は別評価へ分離する。
