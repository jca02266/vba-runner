## 評価内容

標準モジュールにあるイベント名一致SubがWithEventsイベントへ誤って接続されないことを確認する。

## 実施方法

```vba
' Publisher.cls
Option Explicit
Public Event StatusChanged(ByVal value As Long)

Public Sub Fire()
    RaiseEvent StatusChanged(7)
End Sub

' Module1.bas
Option Explicit
Public seen As String
Public Sub Source_StatusChanged(ByVal value As Long)
    seen = "module:" & CStr(value)
End Sub

Public Function Caller() As String
    Dim source As New Publisher
    source.Fire
    Caller = seen
End Function
```

標準モジュールの手続きだけを配置して`Caller`を実行し、イベントが暗黙に接続されるかを確認する。クラス内の正規Subハンドラーを置いた対照も確認する。

## 期待値

プログラム上の期待出力: 標準モジュールSubは無効なハンドラーなので`Caller=""`。

文章での期待: Event Handler DeclarationはWithEvents変数を含む同一クラスモジュール内のSubでなければならず、通常モジュールの同名手続きは候補にならない。

## 結果

プログラム上の実測出力: 修正前はRunnerが標準モジュールSubをfallback登録し、`Caller="module:7"`を返した。修正後は`Caller=""`。

文章での結果: `bindWithEventsHandlers`がクラス候補なしで`env.getProcedure`へfallbackし、所属モジュールとSub種別を検査しないため、仕様上無効な標準モジュール手続きがイベントを受け取った。

## 判定

判定状態: fixed。

独立評価は標準モジュールSubだけの最小構成で`module:7`を再現した。クラス所有のWithEventsでは標準モジュールfallbackを禁止する修正と回帰テストにより`Caller=""`を確認した。トップレベルWithEventsの既存配線は維持した。Interface・ホスト拡張は未解決候補へ移管し、RC-00126は未確定仮説として追跡する。
