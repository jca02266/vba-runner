## 評価内容

LongLong数値式をCBoolへ渡したとき、数値式の一般契約どおりに真偽値へ変換されるかを確認する。

## 実施方法

次の自己完結VBAを実行する。

```vb
Option Explicit
Public Function Probe() As String
    Dim one As LongLong, zero As LongLong, errNo As Long, out As String
    one = CLngLng("1")
    zero = CLngLng("0")
    On Error Resume Next
    Err.Clear
    out = "ONE=" & CStr(CBool(one)) & " ERR=" & CStr(Err.Number)
    Err.Clear
    out = out & "|ZERO=" & CStr(CBool(zero)) & " ERR=" & CStr(Err.Number)
    Probe = out
    On Error GoTo 0
End Function
```

## 期待値

プログラムとしての期待出力:

```text
ONE=True ERR=0|ZERO=False ERR=0
```

CBoolの引数は数値式を受け付け、0以外をTrue、0をFalseへ変換する。LongLongは64ビット数値型なのでこの契約から除外されない。

## 結果

修正前のランナー実測出力:

```text
ONE=Error:13 ERR=13|ZERO=Error:13 ERR=13
```

LongLongがbigintとしてvbaToBooleanの型分岐に入らず、Type mismatch（Error 13）になった。

修正後のランナー実測出力:

```text
True|False|True
```

LongLongとLongPtrのbigintを0nとの比較で変換し、期待どおりの真偽値になった。

## 判定

判定状態: fixed

Microsoft Learnの型変換仕様とLongLongの型定義を独立レビューで確認した。vbaToBooleanへbigint分岐を追加し、LongLong/LongPtrの回帰テストを通過させた。
