# 混在名前付き引数の評価順序

## 再現

独立評価で、標準モジュールの手続きに存在しない `bogus:=` を渡すと、Runnerは
エラーを出さず、未知引数を無視してOptional既定値を使用した。

```vba
Function Build(ByRef state As Long, ByVal leftText As String, _
               Optional ByVal rightText As String = "R") As String
    state = state + 2
    Build = leftText & ":" & CStr(state) & ":" & rightText
End Function

Function InvalidNamed() As String
    Dim state As Long
    InvalidNamed = Build(state, leftText:="L", bogus:="Q")
End Function
```

修正前の実際の結果は `L:2:R` だった。VBAでは未知名前付き引数はError 448
（Named argument not found）として拒否されるべきである。

## 原因と修正

標準モジュール手続きのinline binderは、名前付き引数をMapへ格納していたが、
`proc.parameters`との名前照合を行っていなかった。標準モジュール経路にもError 448の
照合を追加し、回帰テストを追加した。混在引数のソース順評価は既存の共通経路で維持される。

## 検証

最小再現、`call-named-params.test.ts`、`evaluation-state.test.ts`を実行した。
横展開監査では、module-qualified、class、Property、interface、builtin経路は既に
未知名検査済みであることを確認した。Tier 6特殊fallbackだけは仕様・到達性未解決として残した。
