## 評価内容

標準Module AのPublic Property Getを、別ModuleからModule名で修飾して呼び出す。引数付き
Get、0引数Get、Getの戻り値への添字という3つの入口を同じ行列でRunnerとExcelへ渡す。

## 実施方法

`ExcelQueueQualifiedProperty.bas`に次を置き、`ExcelQueueVerification.bas`から呼び出す。

```vba
' ExcelQueueQualifiedProperty.bas
Public Property Get Item(ByVal index As Long) As Long
    Item = index * 10 + 5
End Property

Public Property Get Name() As String
    Name = "module-a"
End Property

Public Property Get Values() As Variant
    Values = Array(10, 20, 30)
End Property
```

```vba
' ExcelQueueVerification.basの評価手続き
On Error Resume Next
Err.Clear: value = ExcelQueueQualifiedProperty.Item(1): errNo = Err.Number
Err.Clear: value = ExcelQueueQualifiedProperty.Name: errNo = Err.Number
Err.Clear: value = ExcelQueueQualifiedProperty.Values(1): errNo = Err.Number
On Error GoTo 0
```

各行を単独のケースとして実行し、`Err.Number`と戻り値をXL-221へ出力する。

## 期待値

期待出力: `ITEM`は15、`NAME`は`module-a`、`VALUES`はArray(10,20,30)の2番目要素20、
いずれも`Err=0`。ただし、この期待値は仮説であり、Excel実機結果で検証する。

文章としては、モジュール修飾がProperty Getの種類を壊さず、0引数の暗黙Getと戻り値添字を
引数付きGetと同じProperty意味論で処理することを期待する。

## 結果

Runner実測出力: `ITEM ERR=0 VALUE=15`、`NAME ERR=5`（Module名前解決エラー）、
`VALUES ERR=450`（Wrong number of arguments or invalid property assignment）。Excelの
XL-221結果は未取得であり、期待値の確定とバグ判定を保留する。

## 判定

判定状態: needs-excel-probe

Runnerで修飾Property Getの経路差を再現したが、Excelの仕様結果が未確定である。XL-221を
準備済みWorkbookへ反映し、実機結果を取得してから`verified-no-bug`、`bug-found`、または
`known-limit`へ遷移する。
