## 評価内容

ランナーで修正済みのScalar ByRef型不一致が、Excelの標準Module・Class・Property・CallByNameでも同じ実行前エラーになるかを確認する。

## 実施方法

次の最小ソースをCompileError用のExcelキューへ登録し、IntegerとDoubleをByRef Longへ渡した時のError番号と値を記録する。

```vba
Private Sub TakeLong(ByRef value As Long)
    value = value + 1
End Sub

Public Sub ProbeByRefMismatch()
    Dim integerValue As Integer, doubleValue As Double, errNo As Long
    integerValue = 10
    doubleValue = 10.5
    On Error Resume Next
    Err.Clear: TakeLong integerValue: errNo = Err.Number
    Debug.Print "INTEGER ERR=" & CStr(errNo) & " VALUE=" & CStr(integerValue)
    Err.Clear: TakeLong doubleValue: errNo = Err.Number
    Debug.Print "DOUBLE ERR=" & CStr(errNo) & " VALUE=" & CStr(doubleValue)
    On Error GoTo 0
End Sub
```

## 期待値

プログラム上の期待値は、両ケースが`ERR=13`で値10および10.5を保持することである。Excel実機結果を根拠に、CallByNameとPropertyを含む各入口の型契約を確定する。

## 結果

ランナー側の回帰テストは期待値を満たしている。現在のExcelQueueVerification.bas/resultにはXL-208のプローブ結果が揃っておらず、Excel実機での比較は未実施である。

## 判定

判定状態: needs-excel

XL-208をExcelQueueVerification.basへ追加して実機結果を取得し、`excel-sync`で同期確認した後に判定を確定する。
