## 評価内容

宣言元とは別の標準モジュールでPrivate UDTを非修飾宣言し、宣言元のPublic ByRef手続きへ渡した場合に、VBAの可視性エラーとして拒否されるかを確認する。

## 実施方法

```vba
' Producer.bas
Option Explicit
Private Type T
    X As Long
End Type

Public Sub Mutate(ByRef value As T)
    value.X = 9
End Sub

' Caller.bas
Option Explicit
Public Function RunProbe() As Long
    Dim value As T
    value.X = 3
    Producer.Mutate value
    RunProbe = value.X
End Function
```

`RunProbe`を実行し、Caller.basの`Dim value As T`が型名を解決して実行まで進むかを確認する。同一Producer.bas内での`T`利用は対照として許容する。

## 期待値

プログラム上の期待出力: Caller.basの`RunProbe`は実行前に「ユーザー定義型が定義されている必要があります」相当のコンパイルエラーとなり、数値を返さない。

文章での期待: Private UDTの可視範囲は宣言モジュールに限られるため、別モジュールの非修飾型名解決とPublic手続き呼出しは静的に拒否される。

## 結果

プログラム上の実測出力: `RunProbe=9`。

文章での結果: RunnerはCaller.basの非修飾`T`を共有型として解決し、`Producer.Mutate`を実行した。コンパイル時の可視性エラーにならず、Private Typeのモジュール境界を越えて値を書き戻した。

## 判定

判定状態: fixed（Private Typeのモジュール境界を修正し、回帰確認済み）。

独立評価で最小ケースを再現し、MS-VBALのPrivate UDT可視性規則と不一致を確認した。横展開ではUDT配列ByRefにも同じ型検査欠落があり、戻り値・Module.Type修飾・クラス境界は別契約として未解決に残した。RC-00120の仮説は本事象を説明するが、Public署名検査は補助経路として分離して受入条件に追加する。
