## 評価内容

VBEが出力するクラスモジュールで、クラス属性ヘッダーと`Option Explicit`を
同時に含む場合のLSP診断を確認する。未宣言変数を1つ置き、通常モジュールと
クラスモジュールで意味検査の結果が一致するかを評価する。

## 実施方法

次の内容を`.cls`文書としてLSPServerへ登録し、`getDiagnostics`の全診断を確認する。

```vba
VERSION 1.0 CLASS
BEGIN
  MultiUse = -1
END
Attribute VB_Name = "OptionExplicitClass"
Option Explicit

Public Sub Verify()
    missing = 1
End Sub
```

同じ手続き本体を`Option Explicit`付きの標準モジュールとしても解析し、診断の
種類を比較する。クラス属性の有無で結果が変わらないことを確認する。

## 期待値

期待出力: clsDiagnostics=[VBA013:0, undeclared:1], basDiagnostics=[VBA013:0, undeclared:1]

プログラム上の期待値は、クラス入力で`VBA013`（Option Explicit欠落）が0件で、
`missing`に対する未宣言変数診断が1件になることである。標準モジュールも同じ
未宣言変数診断を1件返す。

文章上の期待値は、VBEヘッダーを持つ`.cls`であっても`Option Explicit`が
モジュールレベルの意味検査へ伝わり、モジュール形式だけを理由に検査が省略
されないことである。

## 結果

実測出力: clsDiagnostics=[VBA013:1, undeclared:0], basDiagnostics=[VBA013:0, undeclared:1]

修正前の`.cls`は`VBA013: Option Explicit is missing`を1件返し、`missing`の
未宣言変数診断を返さなかった。同じ本体を`.bas`で解析すると、`missing`の
未宣言変数診断が返り、`VBA013`は発生しなかった。

この差は`parseClassBody`が`Option Explicit`をASTへ保存していないため、
`checkOptionExplicit`が未宣言変数検査を早期終了している経路と一致する。

## 判定

判定状態: bug-found

独立レビューにより、クラスOption文のAST保持とクラス単位のOption Explicit検査が
必要であることを確認した。直接修正と真因対処を実装中であり、二次入口の横展開は
別候補として継続する。
