## 評価内容

VS CodeのLSP診断で、ワークスペースに存在する別モジュールのProperty Getを
修飾参照した代入式が、Property名によって異なる診断経路へ入らないか確認する。

## 実施方法

`ExcelQueueQualifiedProperty.cls`をワークスペース文書として登録し、次の最小
標準モジュールをLSPServerへ渡す。

```vba
Option Explicit
Sub Verify()
    Dim value As Variant, errNo As Long
    Err.Clear: value = ExcelQueueQualifiedProperty.Name: errNo = Err.Number
    Err.Clear: value = ExcelQueueQualifiedProperty.Values(1): errNo = Err.Number
End Sub
```

`getDiagnostics`の`source = "vba-runner"`診断を、未知の修飾子を使う対照例と
比較する。

## 期待値

期待出力: 既知クラスを修飾した2つの参照は`vba-runner`診断0件、未知の
`UnknownQualifiedModule.Name`は未宣言診断1件。

文章上の期待値は、`.Name`の通常のMemberExpressionと`.Values(1)`のCallExpressionが
同じ既知モジュール修飾子契約で検査され、Property名や呼び出し形式で結果が変わらない
ことである。

## 結果

実測出力: 修正前は`ExcelQueueQualifiedProperty.Name`の代入で
`Variable 'ExcelQueueQualifiedProperty' not declared`が1件発生した。
一方、`ExcelQueueQualifiedProperty.Values(1)`はCallExpressionの別経路で診断されなかった。
クラス文書をロード済みでも、`getDiagnostics`が`knownModuleNames`を渡していなかった。

修正後はTest 10で既知クラスの2参照が診断0件、未知の修飾子が未宣言診断になることを
確認した。

## 判定

判定状態: bug-found
