## 評価内容

別の標準モジュールにあるPrivate Subが、クラスのWithEventsイベントへ誤って接続されないことを確認する。

## 実施方法

```vba
' Publisher.cls
Option Explicit
Public Event Changed()

Public Sub Fire()
    RaiseEvent Changed
End Sub

' Listener.cls
Option Explicit
Private WithEvents Source As Publisher

Public Sub Init()
    Set Source = New Publisher
    Source.Fire
End Sub

' Handler.bas
Option Explicit
Public fired As Long

Private Sub Source_Changed()
    fired = fired + 1
End Sub

' Runner.bas
Option Explicit
Public Function Caller() As Long
    Dim listener As New Listener
    listener.Init
    Caller = fired
End Function
```

`Caller`を実行し、Handler.basのPrivate Subがイベントを受け取るかを確認する。同一Listenerクラス内に正規Subを置いた対照も確認する。

## 期待値

プログラム上の期待出力: `Caller=0`。

文章での期待: Event Handler DeclarationはWithEvents変数を含むクラスモジュール内のSubでなければならず、別標準モジュールのPrivate Subは候補にならない。

## 結果

プログラム上の実測出力: 修正前はRunnerがHandler.basのPrivate Subをfallback登録し、`Caller=1`を返した。修正後は`Caller=0`。

文章での結果: イベント候補探索が標準モジュール全体を検索し、callback再呼出しにも所有モジュールを渡さないため、Private可視性とクラス所有境界を越えて実行された。

## 判定

判定状態: fixed。

独立評価は4モジュールの最小構成で`fired=1`を再現した。クラス所有のWithEventsでは標準モジュールfallbackを禁止する修正とPrivate Subの回帰テストにより`Caller=0`を確認した。Interface、host extension、subscriber破棄時detachはRCA-PRIVATE-VISIBILITY-018等へ分離し、RC-00127は未確定仮説として追跡する。
