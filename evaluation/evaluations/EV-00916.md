## 評価内容

VBEがエクスポートしたクラスモジュールで、Property宣言の直後に置かれる
メンバー属性をLSP診断が正しく受理するか評価する。

## 実施方法

次のクラスモジュール断片を、`.cls`文書としてLSPServerへ渡し、
`getDiagnostics`の`vba-runner`診断を確認する。

```vba
VERSION 1.0 CLASS
BEGIN
  MultiUse = -1
END
Attribute VB_Name = "ExcelQueueDefaultValue"
Option Explicit
Public Property Get Value() As Variant
Attribute Value.VB_UserMemId = 0
    Value = 1
End Property
```

修正前の診断結果と、`tests/lsp/server-diagnostics.test.ts`のTest 9による
修正後の結果を比較する。これはVBEのメタデータを含むLSP診断の評価であり、
VBA実行時のProperty動作を評価するものではない。

## 期待値

プログラム上の期待値: `getDiagnostics("ExcelQueueDefaultValue.cls")`が
`source = "vba-runner"`の診断を0件返す。

文章上の期待値: `Attribute Value.VB_UserMemId = 0`は実行文ではなくVBEの
メンバー属性メタデータなので、Property本体の構文エラーとして報告しない。

## 結果

修正前は`Value.`付近に`Expected '=' after Attribute name`の
`vba-runner`診断が1件発生した。`parseAttributeStatement`が属性名を単一の
識別子として読み、`getDiagnostics`もクラス解析モードを使っていなかった。

`7ae9b2e1`で属性名の修飾部分を連結し、`.cls`診断を`parseAsClass`で解析する
よう修正した。修正後はTest 9を含む`npx tsx tests/lsp/server-diagnostics.test.ts`
が通過し、対象診断は0件になった。

## 判定

判定状態: fixed

LSP診断の直接修正と回帰テストは完了した。クラス属性を扱う他のLSP入口は
横展開監査で確認し、別の未修正経路が見つかった場合は別評価候補に分離する。
