## 評価内容

VBEからエクスポートしたクラスモジュールを、LSP診断以外のcode action、テスト実行、デバッグ、折りたたみ入口へ渡したとき、診断経路と同じヘッダー除去・クラス解析が適用されるかを確認する。

## 実施方法

次のVBE形式`.cls`を各入口へ渡す。

```vba
VERSION 1.0 CLASS
BEGIN
  MultiUse = -1
END
Attribute VB_Name = "EntryProbe"
Option Explicit

Public Property Get Value() As Variant
Attribute Value.VB_UserMemId = 0
    Value = 1
End Property

Public Sub Test_Attribute()
Attribute Test_Attribute.VB_Description = "probe"
End Sub
```

`getDiagnostics`を基準経路として、`runTests`、DebugAdapter、`getCodeActions`、extensionのfolding providerを同一内容で比較する。各入口の実装が`stripVBAFileHeader`と`parseAsClass`を適用しているかもソースで確認する。

## 期待値

期待出力: すべての入口でVBEヘッダーと属性行を実行文として扱わず、クラスASTを生成する。`runTests`は`Test_Attribute`をpassed、DebugAdapterはparse warningや`BEGIN`実行エラーなし、foldingはクラス内手続きの範囲を返す。code actionはクラスASTを受け取る。

```text
DIAGNOSTICS=0
RUN_TEST=passed
DEBUG_PARSE_WARNINGS=0
DEBUG_BEGIN_RUNTIME_ERRORS=0
FOLDING_RANGES>=1
CODE_ACTION_AST=ClassDeclaration
```

## 結果

実測出力:

```text
DIAGNOSTICS=0
RUN_TEST=Parse error: unexpected token 'CLASS' after statement at line 1
DEBUG_PARSE_WARNINGS=Line 1: unexpected token 'CLASS'; runtime error 35: Sub or Function not defined: 'BEGIN'
FOLDING_RANGES=0
CODE_ACTION=Extract Function returned, but AST was top-level procedure rather than ClassDeclaration
```

`getDiagnostics`は修正済み経路として正常だったが、`test-runner.ts`は生のVBEヘッダーを通常Parserへ渡し、`debug-worker.ts`もヘッダー除去・クラス解析指定を行わなかった。extensionのfolding providerも生ソースを直接Parserへ渡すため範囲を生成できない。code actionと一部extension処理は属性エラーを出さないものの、URIを渡さずクラス文脈を失う未適用経路だった。

## 判定

判定状態: fixed。直接原因は、LSPの二次入口でVBEヘッダー除去と`parseAsClass`指定が共有されていなかったことだった。`parseVBAModule`を共通入口としてtest runner、debug worker、code action、folding、extensionの対象Parser経路へ適用し、VBE形式.clsの回帰を通過させた。
