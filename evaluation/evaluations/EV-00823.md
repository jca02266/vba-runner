## 評価内容

必須引数を持つ`Function test(v)`を、戻り値を受け取らず括弧なしの`test`として
呼び出した場合の実行前コンパイル検査を評価する。実機で確認された
「引数は省略できません」が、Runnerの`precheckProc`でも同じ意味として検出される
ことを確認する。

## 実施方法

```vba
Function test(v)
End Function

Sub t()
    test
End Sub
```

同じ境界を永続化するCompileError.basのケースでは、共通ヘルパー
`MyFuncHasArg(x)`を裸呼出しし、生成テストから`precheckProc`を直接検査する。

## 期待値

プログラム上の期待出力: `Compile error: Argument not optional (line 5)`

必須引数を省略したFunction呼出しは、実行時の`On Error`で処理される前に、
Excelがコンパイルエラーとして拒否する。Runnerも同じ事前検査段階で
`Argument not optional`を通知する必要がある。

## 結果

実測出力: `Compile error: Argument not optional (line 5)`

Runnerは`precheckProc`で呼出し先の必須パラメーター数を検査し、実行前に期待どおり
エラーを返した。CompileError.basから生成した32ケースもすべて成功した。

## 判定

判定状態: verified-no-bug

直接のRunner差異は確認されなかった。標準`Sub`/`Function`の暗黙呼出し、明示`Call`、
引数付き呼出しは、必須引数数を比較する同じ`precheckProc`経路を通る。

## 横展開調査

`precheckProc`のCallExpression引数数検査、CallStatementの裸呼出し、括弧付き呼出し、
`On Error Resume Next`中のコンパイル検査抑制、クラス・標準モジュールの解決経路を確認した。
Propertyや修飾メンバーはMemberExpressionの実行時バインダー、動的COM・Collection・
Dictionaryは動的メンバーの別経路であり、今回の静的検査と同じものとは断定しなかった。
これらの未解決境界は別候補へ分離する。
