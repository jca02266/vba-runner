# NPVの同符号キャッシュフロー検証漏れ

独立評価とrootの最小再現で、正の値だけ、または負の値だけを含むValueArrayをNPVへ渡すと、
runnerはエラーにせず数値を返した。MicrosoftのNPV仕様は配列に少なくとも1つの支払いと
受取を要求するため、これは仕様逸脱である。

直接原因はNPV実装が値列の正負を検証していないこと、設計上の真因はIRR/MIRRと共通する
キャッシュフロー領域検証が共有されておらず、関数ごとに条件が分散していることと分析した。
直接修正後はNPVの正負チェックを追加し、IRR/MIRRの回帰とOption Base 1を確認する。
Excelのエラー番号は未照合なので、番号を仕様として固定せず実機照合候補として残す。
