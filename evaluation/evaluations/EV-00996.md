## 評価内容

Private UDT配列を戻り値に持つPublic Functionを別モジュールからVariant経由で受け取れるかを確認する。

## 実施方法

```vba
' ModuleA
Option Explicit
Private Type T
    X As Long
End Type

Public Function MakeArr() As T()
    Dim values() As T
    ReDim values(0 To 1)
    values(0).X = 7
    values(1).X = 9
    MakeArr = values
End Function

Public Function SameModule() As Long
    Dim values() As T
    values = MakeArr()
    SameModule = values(0).X + values(1).X
End Function

' ModuleB
Option Explicit
Public Function Caller() As Long
    Dim values As Variant
    values = ModuleA.MakeArr()
    Caller = values(0).X
End Function
```

`ModuleA.SameModule`を対照実行した後、`ModuleB.Caller`を実行し、Private UDT配列の境界挙動を比較する。

## 期待値

プログラム上の期待出力: 同一モジュールの対照は`16`。別モジュールの`Caller`はPrivate UDT配列をVariantへLetできず、仕様確認済みのエラーになる（現時点では仮説）。

文章での期待: Private UDTの所有モジュールと配列要素型の可視性が、Public戻り値とVariantへのLet-coercionに適用される。

## 結果

プログラム上の実測出力: `SameModule=16`、別モジュールの`Caller=7`、`TypeName(ModuleA.MakeArr())=T()`。

文章での結果: RunnerはPrivate UDT配列を別モジュールのVariantへ渡し、要素を参照できる状態にした。これは仕様・Excelの適用範囲確認前の差異候補であり、バグ確定ではない。

## 判定

判定状態: in-progress（配列UDTのVariant変換に対する仕様・Excel根拠を確認中）。
