## 評価内容

`GetFile(...).ParentFolder`が、`GetFolder`と同じFolder操作契約を提供するかを確認する。

## 実施方法

次の自己完結したVBA手続きを実行し、ParentFolderのPath/NameとCopy結果を確認する。

```vba
Sub ProbeParentFolder()
    Dim fso As Object, stream As Object, file As Object, parent As Object
    Set fso = CreateObject("Scripting.FileSystemObject")
    fso.CreateFolder "source"
    Set stream = fso.CreateTextFile("source\child.txt")
    stream.Write "x": stream.Close
    Set file = fso.GetFile("source\child.txt")
    Set parent = file.ParentFolder
    Debug.Print "PATH=" & parent.Path & " NAME=" & parent.Name
    On Error Resume Next
    Err.Clear: parent.Copy "copy"
    Debug.Print "COPYERR=" & Err.Number & " EXISTS=" & fso.FileExists("copy\child.txt")
End Sub
```

## 期待値

期待出力：

```text
PATH=source NAME=source
COPYERR=0 EXISTS=True
```

ParentFolderはFolderオブジェクトなので、Folder.Copyと同じ再帰コピーを提供すると仮定する。

## 結果

実測出力：

```text
Runner: PATH=source NAME=source / COPYERR=438 EXISTS=False
Excel: pending
```

Runnerでは修正前にParentFolderがPath/Nameだけのオブジェクトとなり、CopyがError 438で失敗した。
修正後はCopy、Files列挙、ParentFolder.ParentFolderの連鎖が成功した。

## 判定

判定状態: fixed

Runnerで期待値との差異を再現し、ParentFolderを共通Folder生成経路へ集約した。回帰テストが
通過したため`fixed`へ遷移する。
