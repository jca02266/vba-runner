## 評価内容

既存のBUG-00538で確認した`NPer(0.5, -1E+308, 1E+308, 0, 0)`のError 6が、
符号反転、最大値近傍、利率0・-1、通常値でも一貫するかを同じ評価手続きで確認する。

## 実施方法

```vba
Public output As String

Sub ProbeNPerShapes()
    Dim labels, rates, pmts, pvs, i As Long
    Dim value As Double, errNo As Long
    labels = Array("control-max-cancellation", "sign-reversed", "finite-large", _
        "near-max-mixed", "zero-rate", "minus-one-rate", "normal")
    rates = Array(0.5, 0.5, 0.5, 0.5, 0, -1, 0.05)
    pmts = Array(-1E+308, 1E+308, -1E+308, -1E+307, -1E+308, -1E+308, -100)
    pvs = Array(1E+308, -1E+308, 1E+307, 1E+308, 1E+308, 1E+308, 100)
    ' CASE=control-max-cancellation is the EV-00859/XL-217 control.
    ' Remaining cases are the new surrounding-shape matrix.
    For i = 0 To 6
        On Error Resume Next
        Err.Clear
        value = NPer(rates(i), pmts(i), pvs(i), 0, 0)
        errNo = Err.Number
        output = output & CStr(labels(i)) & ":" & CStr(errNo) & ":" & CStr(value) & ";"
    Next i
    On Error GoTo 0
End Sub
```

## 期待値

プログラムとしては、同じ入力に対するRunnerのError番号と値を記録し、有限な数学結果を
一律にOverflowへ分類していないことを確認する。暫定期待出力は、ケースごとにError番号と
値が決定的に得られ、Excel照合前は仕様差を確定しないことである。

文章としては、最大相殺だけを特別扱いした直接修正が、符号反転や近傍の大値まで誤って
拒否していないかを確認する。Excelとの一致判定は実機結果取得後に行う。

## 結果

Runner実測出力（controlはEV-00859/XL-217の再現用）:

```text
control-max-cancellation:6:0;sign-reversed:6:0;finite-large:0:0.12650482954470985;near-max-mixed:5:0.12650482954470985;zero-rate:6:0.12650482954470985;minus-one-rate:6:0.12650482954470985;normal:0:12.42331961551527;
```

最大相殺と符号反転はError 6、有限な大値・通常値は値を返した。rate=0とrate=-1は
Error 6となったが、これらの境界がExcelの仕様と一致するかは未照合である。したがって、
この評価ではバグを確定せず、未解決境界を実Excel照合へ送る。

## 判定

判定状態: needs-excel

Runner側の形状差は記録できたが、期待値が仮説のままでExcel結果がないため終端判定へ
進めない。XL-219として既存のExcelキューへ行列を追加した。準備済みブックを作成して
実機結果を取得した後、各ケースを個別に判定する。
