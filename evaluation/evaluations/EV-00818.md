## 評価内容

FSO TextStreamの`Read(characters)`について、必須引数を省略した値式
`value = stream.Read`と、明示的な`value = stream.Read()`を比較する。
引数不足を関数オブジェクトの値として返してしまうと、後続の文字列処理へ
誤った値が伝播するため、COMメンバー評価の境界を確認する。

## 実施方法

```vba
Public Function ProbeTextStreamRead() As String
    Dim fso As Object, stream As Object, value As Variant, errNo As Long
    Set fso = CreateObject("Scripting.FileSystemObject")
    Set stream = fso.CreateTextFile("read-required.txt", True, False)
    stream.Write "abc"
    stream.Close
    Set stream = fso.OpenTextFile("read-required.txt", 1, False, 0)

    On Error Resume Next
    Err.Clear
    value = stream.Read
    errNo = Err.Number
    ProbeTextStreamRead = "OMITTED=" & CStr(errNo) & "|" & TypeName(value)
    Err.Clear
    value = stream.Read()
    ProbeTextStreamRead = ProbeTextStreamRead & ";PARENS=" & CStr(Err.Number) & "|" & TypeName(value)
    stream.Close
    On Error GoTo 0
End Function
```

## 期待値

期待出力: `OMITTED=<引数不足エラー>|<関数オブジェクトではない>;PARENS=449|<関数オブジェクトではない>`

MicrosoftのTextStream仕様では`Read`の`characters`引数は必須であり、全量読み取りは
`ReadAll`で行う。したがって、引数を省略した値式が関数オブジェクトを返すのではなく、
引数不足として失敗することを仮説上の期待値とする。エラー番号はExcel実機で確定する。

## 結果

実測出力（Runner）: `OMITTED=0|Object;PARENS=449|Object`

Runnerでは、引数なしの値式がエラーにならず関数オブジェクト相当の`Object`を返した。
明示的な`Read()`も実行後にエラー449を記録するが、戻り値変数には関数オブジェクトが
残る。Excelの同一ソース結果は未取得であり、現時点ではバグを確定しない。

## 判定

判定状態: in-progress

Runner側では仕様仮説との差異候補を再現した。ExcelQueueVerification.basのXL-200を
実機で実行し、エラー番号・戻り値の対応を`excel-sync`で確認してから終端判定する。
