## 評価内容

`Implements`でInterfaceを実装したクラスをInterface型の`WithEvents`変数へ接続し、イベントハンドラーが呼び出されるかを確認する。host extension型の型付き`WithEvents`は仕様上のクラス宣言と異なるため、補助的に別経路として切り分ける。

## 実施方法

```vba
' ISource.cls
Option Explicit
Public Event Fired(ByVal value As Long)
Public Sub Fire(ByVal value As Long)
    RaiseEvent Fired(value)
End Sub

' Source.cls
Option Explicit
Implements ISource
Public Event Fired(ByVal value As Long)
Private Sub ISource_Fire(ByVal value As Long)
    RaiseEvent Fired(value)
End Sub
Public Sub Fire(ByVal value As Long)
    RaiseEvent Fired(value)
End Sub

' Listener.cls
Option Explicit
Private WithEvents Source As ISource
Private seen As Long
Public Sub Init(ByVal value As ISource)
    Set Source = value
    Source.Fire 42
End Sub
Private Sub Source_Fired(ByVal value As Long)
    seen = value
End Sub
Public Property Get Seen() As Long
    Seen = seen
End Property

' Module1.bas
Public Function RunProbe() As Long
    Dim source As New Source
    Dim listener As New Listener
    listener.Init source
    RunProbe = listener.Seen
End Function
```

`RunProbe`を実行し、Interface型`WithEvents`経由のハンドラー値を確認する。併せて、VBAクラスとして登録されていないhost objectを型付き`WithEvents`へ代入する経路は、イベント発火前の型エラーとして別記録する。

## 期待値

プログラム上の期待出力: `RunProbe=42`。型付きhost extension経路はVBAクラス型が存在しないため、イベント発火前に拒否される。

文章での期待: `Implements`実装クラスの実体をInterface型で参照しても、Interfaceが公開するイベントと同一クラス内の正規Subハンドラーが対応してイベントを受信する。host extensionの追加は仕様上実装定義であり、未登録の型名をVBAクラスとして受け入れることは要求しない。

## 結果

プログラム上の実測出力: `RunProbe=42`。注入host objectを未定義の`As HostSource`へ代入する補助経路は`Error 6`で停止し、`As Object`ではイベント値`7`を受信した。

文章での結果: Interface型WithEventsのイベント配線は正常で、Implements dispatchとRaiseEventの組み合わせに不一致はなかった。型付きhost extensionはVBA上のクラス定義がないため利用できず、仕様バグではなく現行のホスト注入制限として切り分けた。

## 判定

判定状態: verified-no-bug。

独立評価ではInterface型WithEventsの最小経路を実行し、期待値と一致した。MS-VBALのWithEvents、Implements、Event Handler、RaiseEvent各規定との対応も確認済みである。host extension typed-WithEventsは未実装だが、仕様上の必須挙動ではないため本評価のバグFindingにはしない。
