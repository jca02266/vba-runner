## 評価内容

複数ファイルを含むフォルダーを既存宛先へoverwrite=Falseでコピーし、途中のファイルが
衝突した場合のエラーと失敗後状態をMemoryFileSystemとNodeFileSystemで比較する。
overwrite=Trueと空の宛先も併せて確認し、失敗時だけ先行コピーが残る経路がないかを調べる。

## 実施方法

```vba
Public Function ProbeCopyFolderCollision() As String
    Dim fso As Object, stream As Object, existing As Object
    Dim errNo As Long, firstExists As Boolean, thirdExists As Boolean, oldText As String
    Set fso = CreateObject("Scripting.FileSystemObject")
    fso.CreateFolder "source"
    Set stream = fso.CreateTextFile("source\first.txt")
    stream.Write "first": stream.Close
    Set stream = fso.CreateTextFile("source\second.txt")
    stream.Write "second": stream.Close
    Set stream = fso.CreateTextFile("source\third.txt")
    stream.Write "third": stream.Close
    fso.CreateFolder "dest"
    Set stream = fso.CreateTextFile("dest\second.txt")
    stream.Write "existing": stream.Close
    On Error Resume Next
    Err.Clear: fso.CopyFolder "source", "dest", False: errNo = Err.Number
    firstExists = fso.FileExists("dest\first.txt")
    thirdExists = fso.FileExists("dest\third.txt")
    Set existing = fso.OpenTextFile("dest\second.txt", 1)
    oldText = existing.ReadAll: existing.Close
    ProbeCopyFolderCollision = CStr(errNo) & ":" & CStr(firstExists) & ":" & oldText & ":" & CStr(thirdExists)
    On Error GoTo 0
End Function
```

上のVBA相当プローブを、既存のFSOテストハーネスへ入力し、MemoryFileSystemを注入した
EvaluatorとNodeFileSystemをsandboxRoot付きで注入したEvaluatorの双方で実行する。
同じfixture（source/first.txt、source/second.txt、source/third.txt、および既存の
dest/second.txt）を作り、overwrite=Falseの衝突、空の宛先、overwrite=Trueの3ケースを
比較する。実装側の確認は
`npx tsx tests/tooling/filesystem-backend-copy.test.ts`、VBA意味論の回帰確認は
`npx tsx tests/spec/filesystem-extra.test.ts`で行う。

## 期待値

期待出力: `58:False:existing:False`

overwrite=Falseで既存ファイルに衝突した場合はError 58相当となり、失敗前に宛先へ
コピーされたファイルを残さず、既存ファイルの内容も変更しないことを期待する。空の
宛先では3ファイルが全てコピーされ、overwrite=Trueでは衝突ファイルも更新される。

## 結果

実測出力:

```text
COLLISION-FALSE=58:False:existing:False
EMPTY-FALSE=0:True:second:True
COLLISION-TRUE=0:True:second:True
```

実測出力（NodeFileSystem）:

```text
COLLISION-FALSE=58:False:existing:False
EMPTY-FALSE=0:True:second:True
COLLISION-TRUE=0:True:second:True
```

`EMPTY-FALSE`と`COLLISION-TRUE`ではfirst/second/thirdの3ファイルが存在し、
`COLLISION-FALSE`では衝突前のfirst/thirdが存在しない。独立評価でも同じ結果を再現し、
現在のNode実装がfs.cpSyncの部分コピーを事前衝突検査で防いでいることを確認した。

## 判定

判定状態: verified-no-bug

MemoryFileSystemとNodeFileSystemは、CopyFolder/CopyDirectoryの衝突失敗時状態を共通化
できている。Node標準fs.cpSyncを直接使った場合の部分コピーは、NodeFileSystemの公開契約
には漏れていないため、追加の製品バグは確認しなかった。
