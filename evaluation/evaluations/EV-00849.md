## 評価内容

引数メタデータを持つ汎用COM/hostオブジェクトの必須引数不足について、裸参照、空括弧、引数不足、正しい引数、名前付き引数、`CallByName`、`With`経路を確認し、通常VBA手続きのError 449と比較する。

## 実施方法

`registerComObject`で2つの必須引数を持つ動的メンバーを登録し、VBAから各呼出し形式を実行した。通常Function/Subには同じ引数数の宣言を用意し、エラー番号と成功時の値を比較した。

## 期待値

期待出力：

```text
動的メンバーの裸参照/空括弧/1引数/CallByName不足 = Error 450
動的メンバーの2引数/名前付き2引数 = Error 0、値 1,2
With経路の不足 = Error 450
通常Function/Subの不足 = Error 449
```

文章による期待値：遅延バインドされたCOM/hostメンバーは、通常のユーザー定義手続きとは異なるVBAエラー番号を維持する。

## 結果

実測出力：

```text
metadata付き動的メンバー: bare=450, empty=450, one=450, two=0:1,2, named=0:1,2
CallByName: 0引数=450, 1引数=450, 2引数=0:1,2
With: bare/empty/one=450
通常Function/Sub: 0引数=449, 1引数=449
```

文章による結果：メタデータ付き動的メンバーではすべての不足引数経路がError 450へ変換され、通常手続きはError 449のままだった。正しい引数と名前付き引数は正常に整列された。

## 判定

判定状態: verified-no-bug

動的メンバーのエラー変換、`CallByName`、`With`、通常手続きとのエラー番号差を確認した。今回のメタデータ付きCOM/host契約の範囲では修正不要である。
