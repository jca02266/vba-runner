## 評価内容

クラス内Private Typeを要素型とする動的配列について、ReDim、要素書込み、ReDim Preserve、Erase、再ReDim後の要素書込みを順に確認する。

## 実施方法

```vba
' ClassCase.cls
Option Explicit
Private Type TItem
    Value As Long
End Type

Private items() As TItem

Public Function Probe() As String
    Dim s As String
    On Error Resume Next
    ReDim items(1 To 2)
    s = "redim=" & Err.Number
    Err.Clear
    items(1).Value = 11
    s = s & ";set1=" & Err.Number
    Err.Clear
    ReDim Preserve items(1 To 3)
    s = s & ";preserve=" & Err.Number
    Err.Clear
    Erase items
    s = s & ";erase=" & Err.Number
    Err.Clear
    ReDim items(1 To 1)
    s = s & ";rebuild-redim=" & Err.Number
    Err.Clear
    items(1).Value = 99
    s = s & ";rebuild-set=" & Err.Number
    Probe = s
End Function

' Module1.bas
Option Explicit
Public Function Caller() As String
    Dim instance As New ClassCase
    Caller = instance.Probe
End Function
```

`Caller`を実行し、配列ライフサイクル各操作のエラー番号を記録する。通常モジュールに同じUDT配列を置く対照経路も実行する。

## 期待値

プログラム上の期待出力: `redim=0;set1=0;preserve=0;erase=0;rebuild-redim=0;rebuild-set=0`。

文章での期待: ReDimとReDim Preserveは宣言済みUDT要素を生成・保持し、Eraseは空の同じ要素型へ戻すため、再ReDim後も要素メンバーへ書き込める。

## 結果

プログラム上の実測出力: 修正後のRunnerは `redim=0;set1=0;preserve=0;erase=0;rebuild-redim=0;rebuild-set=0` を返した。

文章での結果: クラス所有型を配列初期化とReDimの共通経路へ渡したことで、初回・Preserve・Erase・再ReDim後の要素書込みがすべて成功した。

## 判定

判定状態: fixed（クラス内Private UDT配列ライフサイクルを回復し、回帰テストを通過）。

独立評価は最小コードで上記出力を再現した。横展開ではReDim PreserveとEraseが既存要素メタデータを引き継ぐだけで、欠落したクラスUDT型を復元しないことを確認した。独立RCA提案と反証レビューはいずれも、直接原因`class-body-type-not-parsed`と根因仮説RC-00122を支持した。ただしEvent、ByRef、Public/Friend境界は未検証であり、RCA-PRIVATE-VISIBILITY-012へ分離した。RC-00122は未確定仮説である。
