## 評価内容

型サフィックス付き仮引数（`ByRef n&`、`ByRef n%`、`ByRef n#` など）と明示的な
`As`指定について、呼出し元の変数型が一致する場合の書戻し、および一致しない
場合の型検査を、標準モジュールとクラスメンバーで確認する。

## 実施方法

次の最小ソースを標準モジュールとクラスメンバーで実行し、型一致ケースと
型不一致ケースを分けて確認する。

```vba
Private Sub TakeLong(ByRef value As Long)
    value = value + 1
End Sub

Public Sub Probe()
    Dim good As Long, integerValue As Integer, doubleValue As Double
    good = 10
    integerValue = 10
    doubleValue = 10.5
    TakeLong good
    TakeLong integerValue
    TakeLong doubleValue
End Sub
```

ランナーでは型付きByRefの書戻しと、異なる型を渡した場合の現在の挙動を確認した。
公式のByRef型不一致仕様を根拠に、ランナーの実行前検査と回帰テストで確認する。

## 期待値

期待出力：

```text
一致するLong変数: 呼出し元の値が11へ書き戻される
Integer/Double変数: Excelは「ByRef 引数の型が一致しません」を実行前に報告する
```

文章による期待値：仮引数の型指定はcallee内の変換だけでなく、ByRef参照を結ぶ
呼出し元LValueの型契約にも適用される。型不一致を暗黙変換して書き戻してはならない。

## 結果

実測出力：

```text
ByRef LongへLong: 4 -> 5
ByRef LongへInteger: Error 13 (ByRef argument type mismatch)
ByRef LongへDouble: Error 13 (ByRef argument type mismatch)
ByRef型サフィックス（%、&、!、#、@、$、^）: 型登録と一致型の書戻しは正常
標準モジュールとクラスメンバー: 一致型の結果は同じ
```

文章による結果：修正前ランナーは型サフィックスの解析と一致型の書戻しを行う一方、
呼出し元LValueとByRef仮引数の型不一致を暗黙変換していた。修正後は実行前に型不一致を
拒否し、括弧による一時値化と一致型の書戻しを維持する。

## 判定

判定状態: fixed

型付きByRef引数の呼出し元型検査を共通binderへ追加した。直接原因は修正済みで、
標準モジュールとクラスメンバーの回帰テストを通過している。実Excelでの最終照合は
別途XL-208として保持する。
