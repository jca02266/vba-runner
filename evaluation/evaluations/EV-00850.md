## 評価内容

型サフィックス付き仮引数（`ByRef n&`、`ByRef n%`、`ByRef n#` など）と明示的な
`As`指定について、呼出し元の変数型が一致する場合の書戻し、および一致しない
場合の型検査を、標準モジュールとクラスメンバーで確認する。

## 実施方法

次の最小ソースを標準モジュールとクラスメンバーで実行し、型一致ケースと
型不一致ケースを分けて確認する。

```vba
Private Sub TakeLong(ByRef value As Long)
    value = value + 1
End Sub

Public Sub Probe()
    Dim good As Long, integerValue As Integer, doubleValue As Double
    good = 10
    integerValue = 10
    doubleValue = 10.5
    TakeLong good
    TakeLong integerValue
    TakeLong doubleValue
End Sub
```

ランナーでは型付きByRefの書戻しと、異なる型を渡した場合の現在の挙動を確認した。
Excelでは同じソースをCompileErrorキューで開き、型不一致が実行前に検出されるかを
確認する。

## 期待値

期待出力：

```text
一致するLong変数: 呼出し元の値が11へ書き戻される
Integer/Double変数: Excelは「ByRef 引数の型が一致しません」を実行前に報告する
```

文章による期待値：仮引数の型指定はcallee内の変換だけでなく、ByRef参照を結ぶ
呼出し元LValueの型契約にも適用される。型不一致を暗黙変換して書き戻してはならない。

## 結果

実測出力（vba-runner）：

```text
ByRef LongへLong: 4 -> 5
ByRef LongへInteger: エラーなしで暗黙変換・書戻し
ByRef LongへDouble: エラーなしで暗黙変換・書戻し
ByRef型サフィックス（%、&、!、#、@、$、^）: 型登録と一致型の書戻しは正常
標準モジュールとクラスメンバー: 一致型の結果は同じ
```

文章による結果：ランナーは型サフィックスの解析と一致型の書戻しを行うが、
呼出し元LValueとByRef仮引数の型不一致を拒否していない。Excelでの実行前エラーとの
一致は未確認であり、実機プローブ作成後に判定する。

## 判定

判定状態: needs-excel-probe

型不一致の期待値がExcel固有のコンパイル時契約であるため、現時点ではバグ確定を
行わない。CompileError.basへ専用ケースを追加し、実機結果を取得してから、直接原因
（ByRefバインダの型検査欠落）と共通原因（呼出し元型契約の未定義）を分離して判定する。
