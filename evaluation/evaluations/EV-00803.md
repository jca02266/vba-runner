# Property Let配列要素ByRefの最小再現

## 評価内容

Property Letの暗黙ByRef引数へ配列要素を渡したとき、呼出元の配列要素が書き換わる経路を
単独で評価した。

## 実施方法

次の最小VBAモジュールを実行し、`ProbeArrayElement`の戻り値を記録した。

```vba
Class Box
Private seen As Long
Public Property Let Value(ByRef incoming As Long)
  seen = incoming
  incoming = incoming + 1
End Property
Public Function SeenValue() As Long
  SeenValue = seen
End Function
End Class

Function ProbeArrayElement() As String
Dim b As New Box
Dim values(0 To 0) As Long
values(0) = 7
On Error Resume Next
b.Value = values(0)
ProbeArrayElement = CStr(Err.Number) & ":" & CStr(b.SeenValue()) & ":" & CStr(values(0))
End Function
```

## 期待値

プログラム上の期待出力: `0:7:7`

Excel実機で確認した結果を期待値とする。Property Let呼出しは成功し、Property Let内で
観測した値と呼出元の配列要素はいずれも7になる。

## 結果

プログラム上の実測出力: `0:7:7`

Property Letの呼び出し自体は成功し、Property Let内で
受け取った値は7だったが、引数を書き換えた結果は呼出元の配列要素へ反映されなかった。

## 判定

Excel実機のXL-187は`ERR=0 SEEN=7 VALUE=7`だった。runnerの結果も`0:7:7`であり、
実機結果と一致したため、新規バグなしと判定する。BUG-00508は期待値未確定のまま作成した
誤判定記録であり、退役済みの履歴として保持する。
