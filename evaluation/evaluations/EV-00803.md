# Property Let配列要素ByRefの最小再現

## 評価内容

Property Letの暗黙ByRef引数へ配列要素を渡したとき、呼出元の配列要素が書き換わる経路を
単独で評価した。

## 実施方法

次の最小VBAモジュールを実行し、`ProbeArrayElement`の戻り値を記録した。

```vba
Class Box
Private seen As Long
Public Property Let Value(ByRef incoming As Long)
  seen = incoming
  incoming = incoming + 1
End Property
Public Function SeenValue() As Long
  SeenValue = seen
End Function
End Class

Function ProbeArrayElement() As String
Dim b As New Box
Dim values(0 To 0) As Long
values(0) = 7
On Error Resume Next
b.Value = values(0)
ProbeArrayElement = CStr(Err.Number) & ":" & CStr(b.SeenValue()) & ":" & CStr(values(0))
End Function
```

## 期待値

プログラム上の期待出力: 未確定（暫定 `0:7:8`）

Property Letの暗黙ByRef引数へ変更可能な配列要素を渡した場合、Property Let内で引数へ
書き込んだ値が呼出元の配列要素へ反映されることを期待する。MicrosoftのByRef引数仕様を
根拠とする。

## 結果

プログラム上の実測出力: `0:7:7`

Property Letの呼び出し自体は成功し、Property Let内で
受け取った値は7だったが、引数を書き換えた結果は呼出元の配列要素へ反映されなかった。

## 判定

実機でも`0:7:7`となったが、正式なExcelキューのプローブと結果ファイルへの同期が
完了していないため、現時点ではBUG判定を取り消し、`needs-excel-probe`へ戻す。
