## 評価内容

TextStream.Readの必須引数をWithブロック内で省略した値式について、通常の
MemberExpressionと同じ引数不足契約が適用されるかを確認する。FSO.GetFile、Dictionary、
Collectionの類似経路は別の評価候補へ分離する。

## 実施方法

```vba
Public Function Probe() As String
    Dim fso As Object, ts As Object
    Dim x As Variant, out As String
    Set fso = CreateObject("Scripting.FileSystemObject")
    Set ts = fso.CreateTextFile("arity.txt", True, False)
    ts.Write "abc": ts.Close
    Set ts = fso.OpenTextFile("arity.txt", 1, False, 0)
    On Error Resume Next
    Err.Clear
    With ts: x = .Read: End With
    out = "WITHREAD=" & CStr(Err.Number) & ":" & TypeName(x)
    Probe = out
End Function
```

## 期待値

期待出力: `WITHREAD=450:Empty`

Excel実機のXL-200で、必須引数を省略したTextStream.ReadがError 450になることを確認済みである。
With内のReadも同じVBA意味を持つため、関数オブジェクトをVariantへ漏らさず、
引数不足エラーとして扱うことを仮説上の期待値とする。

## 結果

実測出力: `WITHREAD=0:Object`（Runner）

Excel実測出力（XL-204）: `WITH-OMITTED ERR=450 TYPE=Empty`

With内の括弧なしReadが関数オブジェクトを返し、引数不足エラーにならなかった。
他のCOM・コレクション経路はこの評価では判定せず、個別候補で確認する。

## 判定

判定状態: fixed

EV-00818の横展開から分離したWith経路で、Runnerは関数オブジェクトを返し、Excelは
Error 450とEmptyを返した。ソースハッシュ、完了マーカー、XL-204を`excel-sync`で
確認したため、TextStream.ReadのWith経路の差異をbug-foundとして確定する。
