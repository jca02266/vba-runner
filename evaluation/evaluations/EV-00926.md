## 評価内容

Property Getが宣言したLong()配列を、同じClassインスタンスから複数回取得して、別々のtyped配列へ代入する。戻り値の由来情報を代入validatorが破壊的に消費し、2回目だけ型不一致になる可能性を確認する。

## 実施方法

```vba
Class Provider
    Private data(0 To 1) As Long

    Public Property Get Longs() As Long()
        data(0) = 7
        data(1) = 8
        Longs = data
    End Property
End Class

Function Probe() As String
    Dim p As New Provider
    Dim a() As Long, b() As Long
    Dim firstErr As Long, secondErr As Long
    On Error Resume Next
    a = p.Longs
    firstErr = Err.Number
    Err.Clear
    b = p.Longs
    secondErr = Err.Number
    Probe = CStr(firstErr) & ":" & CStr(secondErr)
End Function
```

## 期待値

期待出力:

```text
0:0
```

同じ宣言型のProperty Get配列は各呼出しで正当なLong()戻り値として扱われ、1回目の代入が2回目の型検証へ影響してはならない。

## 結果

実測出力:

```text
0:0
```

現行実装ではProperty Getの呼出しごとに戻り値markerが再付与されるため、提示した直接反復では差異を再現しなかった。戻り値をVariantへ保存して再利用する経路は、静的なtyped配列全体代入診断により実行前に拒否され、同じ契約を検証する入力にならない。marker消費が実害になる条件は未確定である。

## 判定

判定状態: verified-no-bug。Property Getの呼出しごとにLong()戻り値のメタデータが再付与され、同じProperty Getを2回直接typed配列へ代入しても両方ともError 0だった。初回報告の0:13は現ワークツリーで再現できず、この境界のバグとは確定しない。Variantへ保存した配列をtyped配列全体へ代入する静的診断経路は別契約であり、本評価の直接反復結果には含めない。
