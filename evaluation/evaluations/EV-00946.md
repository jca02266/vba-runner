## 評価内容

1次元`Double(0 To 3)`を対照に、固定2次元、両次元の下限を変更した固定2次元、可変
2次元の4ケースを評価する。各配列には第1次元が先に変化する順で同じ
`(-100, 50, 100, 0)`を格納し、コンパイル可否、Error番号、値、型、境界を比較する。

## 実施方法

```vba
Private Sub VerifyMirrArrayRankMatrix()
    Dim oneDim(0 To 3) As Double, fixedTwo(0 To 1, 0 To 1) As Double
    Dim shiftedTwo(1 To 2, 5 To 6) As Double, dynamicTwo() As Double
    Dim value As Variant, errNo As Long
    ReDim dynamicTwo(0 To 1, 0 To 1)
    oneDim(0) = -100: oneDim(1) = 50: oneDim(2) = 100: oneDim(3) = 0
    fixedTwo(0, 0) = -100: fixedTwo(1, 0) = 50
    fixedTwo(0, 1) = 100: fixedTwo(1, 1) = 0
    shiftedTwo(1, 5) = -100: shiftedTwo(2, 5) = 50
    shiftedTwo(1, 6) = 100: shiftedTwo(2, 6) = 0
    dynamicTwo(0, 0) = -100: dynamicTwo(1, 0) = 50
    dynamicTwo(0, 1) = 100: dynamicTwo(1, 1) = 0
    On Error Resume Next
    Err.Clear: value = Empty: value = MIRR(oneDim, 0.1, 0.12): errNo = Err.Number
    EmitMirrArrayRankResult "ONE_DIM", LBound(oneDim, 1), UBound(oneDim, 1), _
        "NA", "NA", errNo, value
    Err.Clear: value = Empty: value = MIRR(fixedTwo, 0.1, 0.12): errNo = Err.Number
    EmitMirrArrayRankResult "FIXED_2D", LBound(fixedTwo, 1), UBound(fixedTwo, 1), _
        CStr(LBound(fixedTwo, 2)), CStr(UBound(fixedTwo, 2)), errNo, value
    Err.Clear: value = Empty: value = MIRR(shiftedTwo, 0.1, 0.12): errNo = Err.Number
    EmitMirrArrayRankResult "SHIFTED_2D", LBound(shiftedTwo, 1), UBound(shiftedTwo, 1), _
        CStr(LBound(shiftedTwo, 2)), CStr(UBound(shiftedTwo, 2)), errNo, value
    Err.Clear: value = Empty: value = MIRR(dynamicTwo, 0.1, 0.12): errNo = Err.Number
    EmitMirrArrayRankResult "DYNAMIC_2D", LBound(dynamicTwo, 1), UBound(dynamicTwo, 1), _
        CStr(LBound(dynamicTwo, 2)), CStr(UBound(dynamicTwo, 2)), errNo, value
    On Error GoTo 0
End Sub

Private Sub EmitMirrArrayRankResult(ByVal label As String, ByVal lb1 As Long, _
        ByVal ub1 As Long, ByVal lb2 As String, ByVal ub2 As String, _
        ByVal errNo As Long, ByVal value As Variant)
    Debug.Print "XL-248 CASE=" & label & " D1=" & CStr(lb1) & ":" & CStr(ub1) & _
        " D2=" & lb2 & ":" & ub2 & " ERR=" & CStr(errNo) & _
        " VALUE=[" & CStr(value) & "] TYPE=" & TypeName(value)
End Sub
```

上記はRunnerで一括実行する。Excelでは2次元配列を渡す式がコンパイルエラーになる
可能性があり、共有キューへ入れると他の評価も停止する。そのためXL-248の4ケースを
独立したコンパイル単位として実行し、コンパイル成功時だけ同じ出力形式で記録する。

## 期待値

プログラム上は1次元対照が`ERR=0`、`TYPE=Double`、値
`0.2044280844030315`付近になる。2次元3ケースは、Excelがコンパイル時に拒否するか、
実行時Error 13とするか、第1次元優先の順序で受理するかを記録し、Runnerと同じ分類・
値になることを期待する。MS-VBALは値の配列順を使うとするが多次元の受理規則を確定
していないため、実機確認前に2次元の期待結果を断定しない。

## 結果

Runner実測出力:

```text
XL-248 CASE=ONE_DIM D1=0:3 D2=NA:NA ERR=0 VALUE=[0.2044280844030315] TYPE=Double
XL-248 CASE=FIXED_2D D1=0:1 D2=0:1 ERR=13 VALUE=[] TYPE=Empty
XL-248 CASE=SHIFTED_2D D1=1:2 D2=5:6 ERR=13 VALUE=[] TYPE=Empty
XL-248 CASE=DYNAMIC_2D D1=0:1 D2=0:1 ERR=13 VALUE=[] TYPE=Empty
```

Runnerでは2次元配列をネスト配列として保持する一方、`toCashFlowValues`がランク情報を
参照せず、内側配列を数値へ変換しようとしてError 13となった。固定・下限変更・可変長で
同じErrorとなり、生JavaScript例外は発生しなかった。Excel実機結果は未取得である。

## 判定

判定状態: needs-excel-probe

XL-248の各ケースを独立したコンパイル単位にするプローブが未作成である。Excelの
コンパイル可否と、実行へ到達した場合のError番号・値・走査順を確認するまで、
RunnerのError 13を互換・不一致のどちらにも確定しない。
