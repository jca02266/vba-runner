## 評価内容

EV-00850で修正されたScalar ByRef型検査が、標準手続きとClassでは適用される一方、Property Letの代入形式でも同じ契約を維持するかを確認する。

## 実施方法

次の各呼出し経路を同じ宣言型で実行し、異型LValueが暗黙変換されずError 13になることを確認する。

```vba
Private Sub TakeLong(ByRef value As Long)
    value = value + 1
End Sub

Public Sub Probe()
    Dim value As Integer
    value = 10
    On Error Resume Next
    Err.Clear: TakeLong value
    Debug.Print "MODULE ERR=" & CStr(Err.Number) & " VALUE=" & CStr(value)
    On Error GoTo 0
End Sub
```

Class、Property、CallByNameについては同じ`ByRef value As Long`宣言を各入口へ配置し、既存の型検査テストで確認した。独立評価ではProperty Letだけ異型Integerを受理する挙動が観測されたため、XL-212でExcel結果を照合する。

## 期待値

プログラム上の期待値は、Property Letの異型Integer LValueもError 13となり、呼出し元の値が10のまま保持されることである。文章上は、型変換・書戻しではなく参照結合時の型契約がすべてのVBA呼出し入口で適用されることを期待する。

## 結果

`tests/spec/byref-scalar-type.test.ts` と `tests/spec/callbyname-byref-type.test.ts` は通過した。標準Module、Class、CallByNameはError 13と値不変になるが、Property Letの異型Integerは現実装で受理されるため、共通binderの適用漏れ候補である。Excel結果は未取得である。

## 判定

判定状態: needs-excel-probe

Property LetのExcel境界を確認するXL-212プローブが未作成である。結果がError 13ならBUGを作成し、RC-00080の真因対処範囲へProperty代入経路を追加する。
