## 評価内容

EV-00850で修正されたScalar ByRef型検査が、標準手続きとClassでは適用される一方、Property Letの代入形式でも同じ契約を維持するかを確認する。

## 実施方法

次の通常Scalar ByRef呼出しと、既存のProperty Let value-tailテストを比較し、通常ByRefとPropertyの実効ByVal契約を区別して確認する。

```vba
Private Sub TakeLong(ByRef value As Long)
    value = value + 1
End Sub

Public Sub Probe()
    Dim value As Integer
    value = 10
    On Error Resume Next
    Err.Clear: TakeLong value
    Debug.Print "MODULE ERR=" & CStr(Err.Number) & " VALUE=" & CStr(value)
    On Error GoTo 0
End Sub
```

Class、Property、CallByNameについては同じ`ByRef value As Long`宣言を各入口へ配置し、既存の型検査テストで確認した。Property Letの最終value引数は実効ByValとしてXL-212でExcel結果を照合する。

## 期待値

期待出力:

```text
XL-212 PROPERTY-LET ERR=0 VALUE=10 SEEN=10
```

プログラム上の期待値は、Property Letの最終value引数が値10を受け取り、呼出し元のInteger値を10のまま保持することである。文章上は、Property Let/Setのvalue-tailを通常のScalar ByRef型契約と混同せず、実効ByValとして扱うことを期待する。

## 結果

実測出力:

```text
XL-212 PROPERTY-LET ERR=0 VALUE=10 SEEN=10
```

`tests/spec/byref-scalar-type.test.ts` と `tests/spec/callbyname-byref-type.test.ts` は通過した。Runnerは`0:10:10`、Excelは`ERR=0 VALUE=10 SEEN=10`となり、Property Letのvalue-tailを実効ByValとして扱う結果が一致した。

## 判定

判定状態: verified-no-bug

XL-212のExcel結果は`ERR=0 VALUE=10 SEEN=10`で、Runnerの`0:10:10`と一致した。Property Let/Setの最終value引数は実効ByValであり、RC-00080の通常Scalar ByRef契約を適用しない。
