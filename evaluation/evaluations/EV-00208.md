# LongLong通常算術の64bit精度

## 再現

独立評価と最小再現の双方で、`CLngLng("9007199254740993")` に対する通常算術を実行した。
修正前は `+1` が `9007199254740992`、`-1` が `9007199254740991`、`*3` が
`27021597764222976`、`\\3` が `3002399751580330`、`Mod 3` が `2` になった。
また、LongLong最大値に1を加えてもError 6にならず、丸められた値が返った。

## 原因と修正

`evaluateBinaryExpressionInner` の通常算術ブロックがBigIntを `Number` に変換してから
演算していた。LongLongを含む整数演算（`+`、`-`、`*`、`\\`、`Mod`）をBigIntで評価し、
結果をLongLong範囲で検査する経路を追加した。EnvironmentのLongLong/LongPtr強制と宣言初期値も
BigIntに統一し、単項 `+` はLongLongをそのまま返すようにした。`CLngLng` のBigInt入力にも
範囲検査を追加した。

## 横展開

ソース監査で同じNumber化経路、宣言初期値、BigInt入力の範囲検査漏れ、単項 `+` の
JavaScript TypeErrorを確認した。`/` と `^` はDouble昇格の仕様上別経路として除外し、
String混在とDecimal/Currencyの一部演算は実Excel照合が必要な未解決項目として分離した。

## 回帰

`tests/spec/binary-longlong.test.ts` に64bit境界の加減乗除、Mod、単項 `+`、範囲超過の
回帰テストを追加した。`npx tsx tests/spec/binary-longlong.test.ts` とTypeScript型検査を通過した。
