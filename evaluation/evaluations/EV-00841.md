## 評価内容

FSOのトップレベル`CopyFolder`ではなく、`GetFolder`が返すFolderオブジェクトの`Copy`メソッドが、宛先と子ファイルを作成するかを評価する。

## 実施方法

次の自己完結したVBA手続きを実行する。

```vba
Sub ProbeFolderCopy()
    Dim fso As Object, folder As Object, stream As Object
    Set fso = CreateObject("Scripting.FileSystemObject")
    fso.CreateFolder "C:\source"
    Set stream = fso.CreateTextFile("C:\source\child.txt")
    stream.Write "payload"
    stream.Close
    Set folder = fso.GetFolder("C:\source")
    folder.Copy "C:\destination"
    Debug.Print "DEST=" & CStr(fso.FolderExists("C:\destination")) & _
        " CHILD=" & CStr(fso.FileExists("C:\destination\child.txt"))
End Sub
```

## 期待値

プログラム上の期待出力は`DEST=True CHILD=True`である。Folder.Copyは取得済みフォルダーを宛先へ再帰コピーし、子ファイルも複製するという仮説である。既存のCopyFolder評価とは呼び出し入口が異なるため、同じ結果を別途確認する。

## 結果

Runnerの実測出力は`DEST=False CHILD=False`で、エラーは発生しなかった。Folder.Copy呼び出し後も宛先と子ファイルが存在せず、無操作として完了している。独立レビューでも同じ結果となり、フォルダー用path objectの`copy`が未実装バックエンドの`cpSync?.`を呼ぶだけであることを確認した。
