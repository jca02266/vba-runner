## 評価内容

クラスモジュールで宣言したPrivate Typeを、クラスのPrivate固定配列に保持し、Public Functionから要素を初期化して読み出す経路を確認する。

## 実施方法

```vba
' ClassCase.cls
Option Explicit
Private Type TItem
    Value As Long
End Type

Private items(0 To 1) As TItem

Public Function Probe() As Long
    items(0).Value = 7
    Probe = items(0).Value
End Function

' Module1.bas
Option Explicit
Public Function Caller() As Long
    Dim instance As New ClassCase
    Caller = instance.Probe
End Function
```

`Caller`を実行し、クラス内Private UDT配列の要素が初期化されて値を返すかを確認する。通常モジュール側の同等なUDT配列を対照経路とする。

## 期待値

プログラム上の期待出力: `Caller=7`。

文章での期待: Private Typeは宣言クラス内で参照可能であり、固定配列の各要素はUDTとして既定値で生成され、メンバーへの代入と読み出しが成立する。

## 結果

プログラム上の実測出力: 修正後のRunnerは`Caller=7`を返した。

文章での結果: クラス本体のTypeDeclarationをインスタンス環境へ登録し、固定配列要素のUDT実体化へ同じ環境を渡すことで、要素のメンバーアクセスが成立した。

## 判定

判定状態: fixed（クラス内Private UDT固定配列を回復し、回帰テストを通過）。

独立レビュー: `class_udt_array_horizontal` はParserの`parseClassBody`にType分岐がなく、Evaluatorにもクラス所有型スコープ登録がないことをソース行で確認した。独立実行でも固定配列要素への代入行でError 91を再現し、通常モジュール対照は成功した。`class_udt_array_rca2` は固定配列の再現とRC-00122への統合が妥当としたが、Event経路は未検証のため別候補で扱うべきと補足した。両レビューは補足（supplement）であり、RC-00122自体は未確定仮説として扱う。仕様引用は§5.2.3.1のクラスメンバー配列と§5.2.3.3のPrivate UDT可視性に限定して確認済みである。
