## 評価内容

同じ初期状態を用意したMemoryFileSystemとNodeFileSystemで、mkdirSyncの新規作成、
既存ディレクトリ、既存ファイル、親欠落、recursive作成と再実行を比較する。
Memory側では先にルートをrecursive作成し、Node側ではsandboxの一時ルートを用いて、
バックエンドのルート準備差が結果に混入しないようにする。

## 実施方法

TypeScriptの同一マトリクスを各バックエンドへ適用する。各ケースは例外コードまたは
成功を記録し、対象がファイルかディレクトリか、親階層が存在するかも確認する。
VBA側の既存回帰は `npx tsx tests/spec/filesystem-extra.test.ts`、バックエンドの
既存確認は `npx tsx tests/tooling/filesystem-backend-copy.test.ts` で実行する。

## 期待値

期待出力:

```text
Memory: new=0 existing-false=EEXIST existing-recursive=0 file=EEXIST missing-parent=ENOENT recursive=0
Node: new=0 existing-false=EEXIST existing-recursive=0 file=EEXIST missing-parent=ENOENT recursive=0
```

親が存在する新規作成とrecursive作成は成功する。既存ディレクトリへのrecursive=False、
既存ファイル、親欠落へのrecursive=FalseはError相当となる。既存ディレクトリへの
recursive=True、親欠落へのrecursive=True、recursive作成の再実行は成功する。
MemoryFileSystemとNodeFileSystemで、これらの結果と対象の型が一致することを期待する。

## 結果

実測出力:

```text
Memory: new=0 existing-false=EEXIST existing-recursive=0 file=EEXIST missing-parent=ENOENT recursive=0 rerun=0
Node: new=0 existing-false=EEXIST existing-recursive=0 file=EEXIST missing-parent=ENOENT recursive=0 rerun=0
```

独立評価では、既存ファイルへのrecursive=Trueも両方でEEXIST、親欠落へのrecursive=Trueと
多重recursive作成・再実行は両方で成功した。エラー番号の付加形式を除き、操作結果、
存在状態、ファイル／ディレクトリ判定は全ケースで一致した。関連テストも通過した。

ケース別の比較結果:

| ケース | recursive | Memory | Node | 対象状態 |
|---|---:|---|---|---|
| 親あり・新規 | false | 成功 | 成功 | ディレクトリ作成 |
| 既存ディレクトリ | false | EEXIST | EEXIST | 既存のまま |
| 既存ディレクトリ | true | 成功 | 成功 | 既存のまま |
| 既存ファイル | false/true | EEXIST | EEXIST | ファイルのまま |
| 親欠落 | false | ENOENT | ENOENT | 未作成 |
| 親欠落 | true | 成功 | 成功 | 親を含め作成 |
| recursive再実行 | true | 成功 | 成功 | 状態不変 |

## 判定

判定状態: verified-no-bug

MemoryFileSystemとNodeFileSystemのmkdirSync契約に、今回のマトリクスで追加の差異は
確認されなかった。VBAのMkDirは既存パスと親欠落を別途Error 75/76として検証済みであり、
バックエンド差異の候補には該当しない。
