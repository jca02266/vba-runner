## 評価内容

String と String$ に Boolean および Date を character 引数として渡したとき、
文字列表示だけでなく生成文字の AscW コードを比較し、文字コード変換と
エラー番号の契約を確定する。

## 実施方法

`ExcelQueueVerification.bas` の `VerifyStringCharacterCode` を実行する。
`String$(1, True)`、`String$(1, False)`、`String$(1, CDate(65))`、
`String$(1, CDate(256))`と、同じ4ケースの`String`について、生成文字へ
`AscW`と`Len`を適用し、`XL-225`としてAPI名・入力・コード値・Err.Numberを
出力する。ランナーでも同じ式を実行し、`String`/`String$`の共有実装経路と
比較する。

## 期待値

期待出力:

Runnerの期待出力は次のとおりである。

```text
String$ True=0:1:255, Date65=0:1:65, False=0:1:0, Date256=0:1:0
String True=0:1:255, Date65=0:1:65, False=0:1:0, Date256=0:1:0
```

Excelの実機値は同じ4ケースで、Trueのみ`ASCW=-1805`、他は
`Date65=65`、`False=0`、`Date256=1`となることを期待する。

## 結果

実測出力:

`XL-225` のExcel結果は次のとおりである。

```text
String$ True=0:1:-1805, Date65=0:1:65, False=0:1:0, Date256=0:1:1
String True=0:1:-1805, Date65=0:1:65, False=0:1:0, Date256=0:1:1
```

RunnerはTrueを255、Date256を0としており、ExcelのANSI文字コード契約と一致しない。

## 判定

判定状態: fixed
