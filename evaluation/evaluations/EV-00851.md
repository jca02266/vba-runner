## 評価内容

Indexed Property Let/Setについて、位置引数、Optional引数の省略、名前付きインデックス、
インデックスなしの代入、Property Set、暗黙のvalue-tailを組み合わせた引数整列を確認する。

## 実施方法

`OptionalPropertyBox`および`OptionalObjectBox`を使い、次の呼出しを実行した。

```vba
b.Item(, 2) = 3
b.Item(index2:=2) = 3
b.Item = 3
Set o.Obj(index2:=2) = t
Set o.Obj = t
```

既存のProperty配列、Interface、ParamArray、CallByNameのマトリクスも実行し、
通常の位置引数と名前付き引数で同じvalue-tail契約が保たれることを確認した。

## 期待値

期待出力：

```text
位置引数: Err=0、index1=0、index2=2、value=3
名前付きindex2: Err=0、index1=0、index2=2、value=3
インデックスなし: Err=0、既定値を使用してvalue=3
Property Setの名前付き・省略: Err=0、既定値を使用
value:=をインデックス側へ明示: Error 450
```

文章による期待値：代入式の右辺だけがProperty setterの最終value引数へ暗黙に束縛され、
前置きのOptional・名前付きインデックスは通常の引数整列規則に従う。value-tailを
インデックス引数として明示する形式は不足・過剰引数として拒否する。

## 結果

実測出力：

```text
Property Let位置引数: 0 / 1:2:3
Optional省略・名前付き引数: 既定値で正常
Property Set名前付き・省略引数: 正常
インデックスなしvalue代入: 既定値で正常
value:=のインデックス側明示: Error 450
既存Property/Interface/ParamArray/CallByName回帰: 全件PASS
```

文章による結果：Indexed Propertyの引数整列、暗黙value-tail、Property Let/Setの
Optional・名前付き経路は期待どおりで、標準・クラス・Interface経路の差異も見つからなかった。

## 判定

判定状態: verified-no-bug

FZ-COVERAGE-20260810-337の範囲では修正不要。引数・ByRef・Property領域について、
今回確認したProperty value-tail経路に未解決の差異はない。
