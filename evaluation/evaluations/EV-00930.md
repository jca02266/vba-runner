## 評価内容

NPerの極端な利率、極端なFV、符号反転、-1近傍の4入力について、定義域エラーとOverflowエラーの分類および戻り値をExcelと照合する。

## 実施方法

```vba
Private Sub VerifyNPerNonFiniteBoundary()
    Dim caseNo As Long, value As Double, errNo As Long
    For caseNo = 1 To 4
        On Error Resume Next
        Err.Clear
        Select Case caseNo
            Case 1: value = NPer(1E+308, -100, 100, 0, 0)
            Case 2: value = NPer(0.5, -100, 100, 1E+308, 0)
            Case 3: value = NPer(0.5, -100, 200, 0, 0)
            Case 4: value = NPer(-0.999999999999, -100, 100, 0, 0)
        End Select
        errNo = Err.Number
        Debug.Print "XL-233 CASE=" & CStr(caseNo) & " ERR=" & CStr(errNo) & _
            " VALUE=" & CStr(value) & " TYPE=" & TypeName(value)
        Err.Clear
        On Error GoTo 0
    Next caseNo
End Sub
```

## 期待値

期待出力:

```text
CASE1 ERR=5 VALUE=0 TYPE=Double
CASE2 ERR=0 VALUE=1737.7353177038774 TYPE=Double
CASE3 ERR=5 VALUE=1737.7353177038774 TYPE=Double
CASE4 ERR=0 VALUE=0.025085812887761672 TYPE=Double
```

各ケースについて`ERR`、`VALUE`、`TYPE`をRunnerとExcelで比較する。Error 5（定義域）とError 6（Overflow）を推測で置き換えず、数値は絶対・相対epsilon内で一致し、Error時は代入前の値を保持することを期待する。

## 結果

実測出力:

Runner観測値:

```text
CASE1 ERR=5 VALUE=0 TYPE=Double
CASE2 ERR=0 VALUE=1737.7353177038774 TYPE=Double
CASE3 ERR=5 VALUE=0 TYPE=Double
CASE4 ERR=0 VALUE=0.025085812887761672 TYPE=Double
```

Excel実測値:

```text
CASE1 ERR=5 VALUE=0 TYPE=Double
CASE2 ERR=0 VALUE=1737.73531770388 TYPE=Double
CASE3 ERR=5 VALUE=1737.73531770388 TYPE=Double
CASE4 ERR=0 VALUE=2.50858128877617E-02 TYPE=Double
```

RunnerとExcelはError番号と型が一致した。N2/N4の差は`CStr`の表示精度であり、数値としては機械epsilon内で一致する。N3は失敗した代入が左辺値を更新せず、直前のN2の値を保持するため一致した。

## 判定

判定状態: verified-no-bug。XL-233の実機結果を同期し、4ケースすべてでRunnerとExcelのError番号・戻り値型・残留値保持が一致した。指数表記の差は表示形式の差であり、数値差異ではない。
