## 評価内容

クラスの`ByRef Long`メソッドを`CallByName`で呼び出し、`Integer`変数を渡した場合の
型不一致検査と呼出し元への書戻しを、通常の直接メンバー呼出しと比較する。

## 実施方法

次の最小ソースをランナーとExcelで実行する。

```vba
Class Worker
    Public Sub TakeLong(ByRef value As Long)
        value = value + 1
    End Sub
End Class

Sub Probe()
    Dim worker As New Worker, value As Integer
    value = 10
    On Error Resume Next
    Err.Clear: CallByName worker, "TakeLong", VbMethod, value
    Debug.Print "ERR=" & CStr(Err.Number) & " VALUE=" & CStr(value)
End Sub
```

## 期待値

Excelの`Err.Number`と`value`を記録し、直接メンバー呼出しのByRef型検査と同じ契約か、
CallByNameのVariant配列による動的呼出し契約として暗黙変換を許すかを確定する。

## 結果

実測出力（vba-runner）：

```text
ERR=0 VALUE=11
```

文章による結果：ランナーのCallByName経路は異型Integerを受理し、Longへ変換した値を
呼出し元へ書き戻す。Excelでの動的呼出し契約は未確認である。

## 判定

判定状態: needs-excel-probe

通常の直接呼出しとは異なる結果を記録したが、ExcelのCallByNameにおけるVariant配列と
ByRef型検査の関係が未確定のため、現時点でバグとは判定しない。
