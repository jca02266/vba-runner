## 評価内容

クラス内Private Typeを要素型とする動的配列をReDimし、配列要素のUDTメンバーを初期化・参照する経路を確認する。

## 実施方法

```vba
' ClassCase.cls
Option Explicit
Private Type TItem
    Value As Long
End Type

Private items() As TItem

Public Function Probe() As Long
    ReDim items(0 To 1)
    items(0).Value = 21
    Probe = items(0).Value * 2
End Function

' Module1.bas
Option Explicit
Public Function Caller() As Long
    Dim instance As New ClassCase
    Caller = instance.Probe
End Function
```

`Caller`を実行し、ReDim後のUDT要素のメンバー代入と読み出しが成立するかを確認する。通常モジュールに同じ動的UDT配列を置く対照経路も実行する。

## 期待値

プログラム上の期待出力: `Caller=42`。

文章での期待: ReDimは宣言された動的配列の境界を設定し、各要素は宣言済みUDTとして既定値で生成されるため、Valueへの代入と読み出しが成立する。

## 結果

プログラム上の実測出力: Runnerは`items(0).Value = 21`で実行時エラー424（Object required）を発生させ、`Caller`は42を返さない。通常モジュール対照は42を返す。

文章での結果: クラス内TypeDeclarationが型環境に登録されず、ReDim後の要素にUDT型メタデータが付かないため、要素がスカラー0へフォールバックし、メンバーアクセスが失敗した。

## 判定

判定状態: bug-found。

独立評価は同じ最小コードでError 424を再現し、通常モジュール対照が42になることを確認した。横展開ではParserの`parseClassBody`にType分岐がないこと、Evaluatorのクラス所有型登録がないこと、ReDimが既存メタデータに依存することを確認した。独立RCA提案と別エージェントの反証レビューはいずれも直接原因`class-body-type-not-parsed`と根因仮説RC-00122を支持したが、EventやPublic/Friend境界は未検証として切り分けた。RC-00122は未確定仮説である。
