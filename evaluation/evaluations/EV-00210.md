# Decimal/Currency整数除算・Modの精度

## 再現

独立評価と最小再現で、`CDec("79228162514264337593543950335")` の整数除算とModを
確認した。修正前の `\\ 3` は期待値
`26409387504754779197847983445` に対し `2.6409387504754778e+28` となり、
`Mod 100000000000000000` は期待値 `64337593543950335` に対し
`64337593543950340` となった。どちらも結果型は`Double`だった。

## 原因と修正

`evaluateDecimalOp` の `\\` と `Mod` がBigInt商・剰余を `Number(...)` へ変換していた。
固定小数点の丸め後にBigIntで演算し、scale 0の`VbaDecimal`として返すように変更した。
これにより桁を保持し、Decimalの型情報も維持する。

## 横展開

Decimalの+/-/*と/は既存の固定小数点経路であり、今回のNumber化バグは確認しなかった。
Currency単独の\\・ModはCurrencyの整数部分がNumber安全域内で、同じ桁落ちは確認しなかった。
非整数Double混在、Currencyの/、戻り型と負数丸めの実Excel仕様は未解決として分離した。

## 回帰

`tests/spec/builtins.test.ts` にDecimal最大値の\\、Mod、結果型の回帰テストを追加した。
組み込みテストとTypeScript型検査を通過した。
